# 实验报告 90 分演示指南

四个板块按 1→2→3→4 顺序展示，覆盖评分标准全部要求。

---

## 第一块：示波器捕获串行数据帧（WS2812 彩灯 RGB）

**对应评分**：示波器捕获串行数据帧波形，彩灯 RGB 展示并解释

**材料**：示波器 + 板子（下载 `task1-1-ws2812.sof`）

**接线**：探头 → PIN_T2，地夹 → 板子 GND

**示波器设置**：
- 时基：~2 µs/div
- 电压：~2 V/div
- 触发：Normal，上升沿，电平 ~1.5V

**看到的波形**：WS2812 NRZ 单线编码

**解释要点**：
1. WS2812 单线协议，1 bit ≈ 1.25 µs
2. 短高 + 长低（~0.4µs / 0.85µs）= 逻辑 0
3. 长高 + 短低（~0.8µs / 0.45µs）= 逻辑 1
4. 每 24 个脉冲 = 一颗 LED 的 GRB 数据（绿 8bit + 红 8bit + 蓝 8bit，MSB first）
5. 8 颗 LED 之间 ≥ 50 µs 低电平（RESET 帧间隔）
6. 指认波形图中：单 bit 的 0/1 编码、一颗灯的 24bit 帧、RESET 间隔

## 第二块：Cy4 qxp 灰盒使用 + HDL 代码建工程（自定义流水灯）

**对应评分**：qxp 灰盒使用和 HDL 代码建工程，自定义流水灯展示并解释

**材料**：板子（同一设计）+ 打开 `task1_top.v` + `ws2812_stub.v`

**代码结构**：

| 模块 | 来源 | 功能 |
|------|------|------|
| `task1_top` | 自写 HDL | 顶层：按键消抖 + 亮度控制 + 流水节拍 + 模式切换 |
| `key_pulse_low` | 自写 HDL | 2 级同步防亚稳态 + 20ms 消抖计数器 |
| `ws2812` | 灰盒 IP (`ws2812-u_ws2812.qxp`) | WS2812 时序发生器 |

**板子演示**：
- **K1** — 亮度减，**K2** — 亮度加（0~15 级共 16 档）
- **L1** — 模式切换（mode 0 ↔ mode 1）
- **L2** — 复位

**两种流水模式**：
- Mode 0：二进制单灯流水，逐位点亮 8 颗 LED
- Mode 1：四进制 RGB 变色（00=灭, 01=绿, 10=红, 11=蓝），四色滚动

**解释要点**：
1. 顶层所有控制逻辑均手写 HDL，灰盒仅封装 WS2812 物理层时序
2. 按键消抖：2 级同步器 → 20ms 计数 → 状态变化确认 → 单周期脉冲输出
3. 流水节拍：50MHz 时钟 10M 分频 ≈ 0.2s/步
4. 这是灰盒 IP 与自写 HDL 协同设计的典型模式

## 第三块：ModelSim 双层 FSM 仿真

**对应评分**：双层状态机仿真，波形图截取时间轴/信号短名字，状态迁移可解释，交互握手可解释

**材料**：打开 `task2_fsm_modelsim_waveform.png`，备选打开 ModelSim 重跑 `run_batch.do`

**双层 FSM 架构**：

```
顶层 (TOP, 7 状态)：事务调度
  IDLE → LATCH_RX → START_SUB → WAIT_SUB → SEND_ACK → DONE
  IDLE → SEND_REQ → DONE

底层 (SUB, 4 状态)：命令执行
  IDLE → APPLY → HOLD → DONE
```

**波形图中指认**：
1. **时间轴** + **信号短名字**：`top_state`, `sub_state`, `sub_start`, `sub_done`, `rx_ready`, `tx_start`, `tx_busy`, `led_mode`
2. **完整流程**：`rx_ready` 脉冲 → `top_state` 从 IDLE 逐级迁移至 DONE → `sub_start` 握手 → `sub_done` 应答 → `tx_start` 发送回显
3. **仲裁场景**：`rx_ready` 与 `req`(K1) 同时到达时，顶层优先进入 LATCH_RX 处理串口字节

**讲解握手**：
- 顶层拉高 `sub_start`（1 个 clk）→ 底层从 IDLE 进入 APPLY
- 底层执行完成（APPLY → HOLD(6 clk) → DONE）
- 底层拉高 `sub_done`（1 个 clk）→ 顶层从 WAIT_SUB 进入 SEND_ACK
- 顶层等 `tx_busy` 空闲 → 发 `tx_start` → 回 DONE → IDLE

**命令合法性**：
- 合法：`0` `1` `2` `3` `A` `a` → 底层解析为 led_mode 0~4 + 回传确认
- 非法：其他字符 → `cmd_reg_valid = 0` → 直接从 LATCH_RX 回 IDLE，不触发底层

## 第四块：Cy4 + Pmod 蓝牙板，自制 UART 收发器

**对应评分**：通信端口建立测试并解释通信双方，自制 UART 收发器展示并解释

**材料**：板子（下载 `task2-1.sof`）+ 串口助手 COM4 115200 8N1

**硬件连接**：

```
PC(串口助手) ←→ 蓝牙 CH9143 ←→ UART ←→ FPGA
                    │               │
              CH9143 TX ────→ PIN_B11 (FPGA rx_din)
              CH9143 RX ←──── PIN_D6  (FPGA tx_dout)
```

**自制 UART 模块**（全部手写 HDL，非 IP）：

| 模块 | 功能 | 关键设计 |
|------|------|---------|
| `uart_tx_byte` | 发送器 | 起始位0 + 8bit LSB first + 停止位1；50M/434≈115200；`tx_busy` 标志防冲突 |
| `uart_rx_byte` | 接收器 | 3 级同步防亚稳态 → 下降沿检测 → 半位确认起始位 → 每 bit 中心采样 → 停止位校验 |

**双层 FSM 仲裁**：

| 事件 | 优先级 | 行为 |
|------|--------|------|
| 串口收到字节(`rx_ready`) | 高 | 立即锁存，合法命令更新 LED + 回传确认 |
| K1 按下(`req`) | 低 | 发送 0x55，遇到 rx_ready 被抢占 |
| TX 忙碌时收新字节 | — | 1 字节 pending 缓冲，当前完成后再处理 |

**现场演示操作**：

| 操作 | 预期结果 |
|------|---------|
| 串口发 `1` | LED 红灯闪烁，回显 `1` |
| 串口发 `2` | LED 绿灯闪烁，回显 `2` |
| 串口发 `3` | LED 蓝灯闪烁，回显 `3` |
| 串口发 `A` | LED 全白闪烁，回显 `A` |
| 串口发 `0` | LED 全灭，回显 `0` |
| 串口发 `X` | 无反应（非法命令被 FSM 丢弃） |
| 按板子 K1 | 串口助手收到 `U`(0x55)，FPGA 主动发送 |

**解释要点**：
1. 通信双方：PC 端蓝牙虚拟串口 ↔ CH9143 蓝牙-UART 桥接 ↔ FPGA 手写收发器
2. 收发器全部手写——起始位/停止位/波特率生成/中心采样均 HDL 实现
3. 双层 FSM = 顶层管"什么时候发/收"、底层管"LED 怎么变"、仲裁防冲突
4. 回显 + LED 控制共用一条链路，验证收发双向通路均正常

## 演示顺序建议

1. **第一块**（示波器）→ 抓 WS2812 波形，讲 NRZ 编码
2. **第二块**（灰盒+HDL）→ 同一个设计，讲代码结构 + 按键调亮度/切模式
3. **第三块**（ModelSim）→ 切到电脑，打开波形截图讲双层 FSM 状态迁移和握手
4. **第四块**（蓝牙+UART）→ 板子下载 task2-1，串口助手现场收发，LED 响应

第一二块共用一套代码（WS2812），第三四块共用双层 FSM 设计，逻辑连贯。
